# 말랑교실 — 디자인 가이드라인

`auth.html`(로그인/회원가입) · `index.html`(학생) · `teacher.html`(선생님) 세 화면의 실제 구현 코드를 기준으로 정리한 디자인 시스템 문서입니다. 새 화면/컴포넌트를 추가할 때 이 문서를 기준으로 삼아 주세요.

---

## 0. 서비스 구성

| 파일 | 대상 | 진입/역할 |
|---|---|---|
| `auth.html` | 선생님 | 서비스 진입점. 로그인/회원가입 탭 전환형 카드. 로그인 성공 시 `teacher.html`로 이동 |
| `teacher.html` | 선생님 | 학급 목록 → (수업 입장 / 학급 관리) 두 갈래. 학급 관리 안에 학생·과제·팀·채팅 관리가 딸려 있음 |
| `index.html` | 학생 | 실시간 수업 화면(WebRTC), 오늘의 과제, 퀴즈, AI 튜터 채팅 |

세 화면 모두 같은 CSS 변수(`:root` 토큰)와 `--font`, `--bounce`, 라운드/그림자 값을 그대로 복제해서 씁니다. 새 화면을 추가할 때도 이 토큰 세트를 그대로 가져가고, 값 자체를 바꾸지 마세요.

**핵심 내비게이션 원칙**: 학급 카드의 "수업 입장"은 곧바로 실시간 수업(WebRTC) 화면으로, 카드 위의 톱니바퀴 아이콘은 학급 관리 대시보드로 — **수업 진행과 관리 기능을 화면 단위로 분리**합니다. 새 진입점을 추가할 때도 "지금 당장 할 일"과 "관리/설정"을 같은 화면에 섞지 마세요.

## 1. 디자인 원칙

> **"색은 기능을 설명한다"**

- 카드/배경은 대부분 **흰색(White)** 이고, 색은 오직 **헤더·아이콘·버튼** 등 의미가 있는 곳에만 사용합니다.
- 컬러 예산(화면 전체에서 차지하는 비율 목표): **White 60% · Blue 20% · Yellow 10% · Mint 7% · Gold 3%**
- 각 색은 한 가지 역할만 담당합니다. 다른 목적으로 재사용하지 않습니다 (예: XP의 Gold는 별점·경험치 전용, 다른 곳에 쓰지 않음).
- 대상 사용자는 초등 저학년 학생 **및** 그들을 가르치는 선생님입니다. 학생 화면은 큰 라운드·통통 튀는 애니메이션·놀이 요소를 적극 사용하고, 선생님 화면은 같은 톤을 유지하되 정보 밀도가 높은 대시보드/리스트/모달 패턴을 더합니다. 톤을 낮추더라도 라운드·bounce 모션·색 예산 규칙은 그대로 따릅니다.
- 선생님 화면에서 새 기능 영역(팀, 과제, 채팅 등)을 추가해도 **새 브랜드 컬러를 만들지 않습니다.** 기존 5색 중 의미가 맞는 색을 재사용하세요 (예: 과제 유형 이모지 배지는 Mint를, 상태 배지는 Sky/Task/Red를 재사용).
- **선생님 화면은 디지털 숙련도가 낮거나 연령대가 높은 사용자도 사용한다는 전제로 설계합니다.** 정보 밀도가 높은 대시보드 톤을 유지하되, 한 화면에서 요구하는 1차 행동은 1~2개로 제한하고 자주 쓰는 기능을 최상단에 노출합니다. 세부 규칙은 10장 참고.

- 정답/오답(`success`, `red`)은 퀴즈 피드백·제출 상태·위험 액션 전용 예외 색상입니다. 일반 UI 강조에는 쓰지 않습니다.
- **역할 배지 색 매핑**은 고정 규칙입니다: Owner = primary 채움, Maintainer = sky 채움. 다른 역할 개념이 추가돼도 이 두 색을 유지하고 새 역할엔 남은 예산 색(Mint 등)을 배정하세요.
- **색만으로 상태를 구분하지 않습니다.** 선생님 화면의 모든 상태 배지·pill(`.status-pill`, `.role-badge`, mic/cam 상태 등)은 색과 함께 아이콘 또는 텍스트 라벨을 반드시 병기합니다. (예: 마이크 꺼짐은 빨강 배경만이 아니라 "끔" 텍스트/아이콘 동반)

## 3. 타이포그래피

- 폰트: `'Pretendard', 'Noto Sans KR', sans-serif` (`--font`)
- 웨이트: 400 / 500 / 700 / 900 만 사용 (Noto Sans KR 로드 웨이트 기준)
- 단어 줄바꿈 방지가 필요한 한글 텍스트에는 `word-break:keep-all` 적용

| 용도 | 크기 | 굵기 |
|---|---|---|
| 페이지 제목 (`h1`, 인사말) | 1.7rem | 900 |
| 카드 제목 (`.task-head h2`) | 2rem | 900 |
| 퀴즈 본문 (`.q-text`) | 1.55rem | 900 |
| 모달 제목 (`.modal-head h2`) | 1.3rem | 900 |
| 섹션 소제목 (`.t-name`, `.celebrate-card h2`, `.section-head h2`) | 1.02–1.35rem | 900 |
| 본문/설명 (`.greet p`, `.t-sub`, `.modal-sub`) | .85–.95rem | 500 |
| 캡션/보조 정보 (`.t-count`, `.xp-num`, 배지 텍스트) | .68–.84rem | 700–900 |
| 버튼 텍스트 | .8–1.05rem | 700–900 |

**규칙**: 강조가 필요한 텍스트(제목, 숫자, 버튼, 배지)는 항상 900 weight. 설명/보조 텍스트는 500 weight로 대비를 분명히 줍니다.

**선생님 화면 예외**: 표의 `.85–.95rem` 캡션 크기는 통계·인원수 같은 보조 정보에만 사용합니다. 인사말, 메인 액션 카드 제목·버튼, 폼 라벨처럼 "지금 무엇을 해야 하는지" 전달하는 텍스트는 최소 `1rem`(16px) 이상을 유지합니다.

## 4. 여백·형태 (Spacing & Shape)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--r-lg` | 28px | 큰 카드 (video-card, task-panel, class-card, panel, modal-card) |
| `--r-md` | 24px | 중간 카드 (teacher-bar, char-panel, stat-card) |
| 완전 원형 | `999px` | 버튼, 칩, 배지, 토스트, 탭 트랙 대부분 |
| `--shadow` | `0 8px 24px rgba(0,0,0,.08)` | 일반 카드 |
| `--shadow-lg` | `0 14px 32px rgba(0,0,0,.08)` | 사이드바, 비디오 카드, 퀴즈 카드, 모달 등 시각적으로 튀는 요소 |

- 그리드 컬럼 간격: `28px` (app), `26px`/`20px` (그리드), `14–18px` (세로 스택/카드 그리드)
- 라운드는 **크게, 각지지 않게** — 각진 사각형 대신 항상 24px 이상의 radius 또는 완전 원형을 사용합니다. 입력창은 16px, 작은 배지/토글은 14px까지 허용.

## 5. 모션

- 기본 이징: `--bounce: cubic-bezier(.34,1.56,.64,1)` — 통통 튀는 느낌. 버튼 hover/active, 카드 등장, 모달 오픈에 기본으로 사용합니다.
- Hover: `translateY(-2px)` ~ `translateY(-4px)` 정도의 미세한 부상 효과
- Active(클릭): `scale(1.04–1.12)` 정도의 눌림/팝 효과
- 등장 애니메이션: `fadeUp .35~.45s var(--bounce)` (퀴즈 전환, 채팅창 오픈, 모달, 마법사 스텝 전환 등)
- 손들기·와글거림처럼 특수 상태는 `wiggle` 계열의 캐릭터성 있는 키프레임 사용
- 토글 스위치(`.switch`)는 `transform:translateX()` + `--bounce`로 손잡이가 팡 튀듯 이동
- **접근성**: `prefers-reduced-motion: reduce` 사용자에게는 모든 애니메이션/트랜지션을 `.01ms`로 강제 단축 — 새 애니메이션 추가 시 이 규칙에 자동으로 걸리는지 확인하세요.

## 6. 컴포넌트 패턴

### 버튼
- Primary 액션: `--primary` 배경 + 흰 텍스트 (`.btn-primary`), 혹은 흰 배경 + `--primary` 텍스트/테두리 (`.btn-outline`)
- 보조 액션: `--sky` 배경 + `--primary` 텍스트 (`.btn-soft`), 중립 액션: 흰 배경 + 그림자 (`.btn-ghost`)
- 위험 액션(삭제/강퇴/종료): `--red-soft` 배경 + `--red` 텍스트 (`.btn-danger`) — 항상 `confirm()` 등 확인 절차를 거친 뒤 실행
- 모든 인터랙션 버튼은 **최소 44px 높이**(터치 타깃, 아동 사용자 및 고령 사용자 고려)를 원칙으로 합니다. 텍스트가 있는 보조 버튼(`.btn-sm`)도 44px을 유지하고, 리스트 행 안의 아이콘 전용 편집/삭제 버튼처럼 정말 부차적인 경우에만 38px까지 예외로 허용합니다.
- 둥근 필(pill) 형태(`border-radius:999px`)가 기본, 사각 카드형 버튼도 큰 radius(16–20px) 유지
- **버튼 텍스트는 동사+목적어로 구체적으로 씁니다.** "저장" 대신 "출석 저장", "확인" 대신 "학생 알림 보내기"처럼 결과를 예측할 수 있게 표기합니다. 특히 선생님 화면에 적용합니다.
- 기능이 비슷한 버튼 3개를 나란히 배치하지 않습니다. 주요 액션은 한 화면에 하나만 강조색(`--primary`)을 쓰고 나머지는 `.btn-soft`/`.btn-ghost`로 톤을 낮춥니다.

### 카드
- 배경은 흰색이 기본, 색이 들어가는 카드는 예외적 (비디오 카드/방송 미리보기의 `--sky`)
- 그림자로 계층을 표현하고 테두리선은 최소화
- 클릭 가능한 카드(학급 카드 등)는 hover 시 `translateY(-4px)` + 그림자 강화로 "떠오르는" 피드백을 줍니다. 카드 안에 별도 액션 버튼이 있다면 `stopPropagation()`으로 카드 전체 클릭과 분리하세요.

### 배지 / 상태 표시
- 역할 배지: Owner = primary 채움, Maintainer = sky 채움 (`.role-badge`)
- 완료 상태: soft 배경 + deep 텍스트 + 체크 아이콘 (`.task-row.done`, `.s-tag.done`)
- 진행 상태 pill: 진행중 = sky, 예정 = task-soft, 종료 = track 회색 (`.status-pill`)
- LIVE: 빨강 배지 + 흰 펄스 도트 애니메이션 (`.live-dot`)
- 안읽음/알림: 작은 빨강 점 (`.unread-dot`), 손들기: task 색 원형 배지 + wiggle

### 모달
- `.modal-overlay`(반투명 배경 + blur) + `.modal-card`(흰 카드, `r-lg` 라운드, `celebIn` 팝 애니메이션)
- 배경 클릭 시 닫힘(`e.target === e.currentTarget` 체크), 우상단 원형 `.modal-close` 버튼 항상 배치
- 여러 단계가 필요하면(과제 생성 등) 상단에 진행 dot(`.wizard-dots`)을 두고 단계별 `.wizard-step.active` 전환

### 폼 입력
- input/select/textarea: `--bg` 배경 + `--bg` 테두리(평소엔 안 보임) → focus 시 `--primary` 테두리로 전환, 라운드 16px
- 검증 실패 시 `.field.invalid`: 테두리 `--red`, 배경 `--red-soft`, 필드 아래 에러 문구 노출(`.field-error`)
- 라벨은 항상 900 weight, 입력창 위에 8px 간격으로 배치 — placeholder만으로 라벨을 대신하지 않습니다.
- 에러 문구는 "무엇이 잘못됐는지"가 아니라 "어떻게 고치면 되는지"로 씁니다. (예: "입력 오류" 대신 "전화번호는 10~11자리 숫자로 입력해 주세요")
- 자주 쓰는 선택지(학년, 과목 등)는 select 드롭다운보다 버튼/칩(`.btn-soft` 계열)으로 바로 노출하고, 선택지가 많을 때만 드롭다운을 씁니다.
- 학급 생성·학생 초대처럼 입력 항목이 3단계 이상인 폼은 한 화면에 몰지 말고 `.wizard-dots`/`.wizard-step` 패턴으로 단계별 분할합니다.
- 자동 저장인지, 저장 버튼을 눌러야 하는지 화면에 명시적으로 표시합니다.

### 토글 스위치 & 토글 버튼
- on/off가 즉시 전체에 영향을 주는 설정(쉬는시간 잠금 등)은 `.switch`(둥근 트랙 + 원형 손잡이)
- on/off가 액션형(음소거하기 등 클릭할 때마다 상태가 바뀌는)인 경우 `.toggle-btn`(텍스트+아이콘이 있는 필 버튼, on 상태는 red 배경)

### 두 갈래 인박스 (채팅 관리)
- 왼쪽 좁은 리스트(고정 폭) + 오른쪽 넓은 상세/스레드 영역의 2단 레이아웃
- 리스트 항목은 안읽음 우선 정렬, 활성 항목은 `--sky` 배경으로 강조
- 말풍선: 상대방(학생) = `--bg` 배경 왼쪽 정렬, 나(선생님) = `--primary` 배경 흰 글씨 오른쪽 정렬 (일반적인 메신저 컨벤션)

### 실시간 수업(WebRTC) 타일
- 학생별 비디오 타일은 `--sky` 배경의 4:3 박스, 카메라 꺼짐 상태는 회색(`.cam-off`)으로 전환
- 타일 위 아이콘 배지(마이크/카메라 상태)는 우상단, 손들기 배지는 좌상단, 이름 라벨은 좌하단 반투명 검정 배경
- 전체 제어(전체 음소거/카메라 끄기)는 개별 타일 제어보다 상위 계층에 별도 바(`.global-controls-row`)로 배치해 "일괄 vs 개별" 조작을 시각적으로 구분

### 아이콘
- 모든 아이콘은 인라인 SVG `<use>` 심볼로 정의 (`#ic-*`), `fill="currentColor"` 또는 `.fill` 클래스로 색 제어
- 24x24 viewBox 기준, 실제 렌더 크기는 13~26px

### 캐릭터/마스코트
- 원형 프레임, `drop-shadow`로 입체감
- hover 시 `translateY(-4px) scale(1.08)`로 살아있는 느낌 부여

## 7. 레이아웃 & 반응형

### 학생 화면 (`index.html`)
- 최대 폭 `1500px`, 메인 그리드 `minmax(0,1fr) 400px` (좌: 방송/과제 수행, 우: 오늘의 과제 고정폭)
- 뷰포트 전체 배율(zoom) 스크립트로 1280x800 기준 비율 유지

### 선생님 화면 (`teacher.html`)
- 최대 폭 `1400px`, 사이드바는 `.app`(flex, `align-items:stretch` 기본)에서 **`align-self:stretch`로 오른쪽 콘텐츠와 항상 같은 높이**를 유지합니다. `flex-start`로 고정하지 마세요 — 화면마다 콘텐츠 길이가 달라 사이드바가 짧아 보이는 버그가 됩니다.
- 카드 그리드는 `repeat(auto-fill, minmax(Npx,1fr))` 패턴 재사용 (학급 카드 260–280px, 팀 카드 260px, 학생 타일 150px 등 화면별로 최소폭만 다름)
- 수업 진행 화면은 `340px(내 방송) + 1fr(학생 그리드)` 2컬럼, 1120px 이하에서 1컬럼으로 전환

### 인증 화면 (`auth.html`)
- 사이드바 없이 화면 중앙 정렬된 단일 카드(`max-width:440px`), 배경에 은은한 blob 장식 2개
- 로그인/회원가입은 탭 전환(같은 카드 안에서 패널만 교체)이며 별도 라우팅 없이 자바스크립트로 처리

### 공통 브레이크포인트
- `1120px 이하`: 2컬럼 grid → 1컬럼
- `640px 이하`: 모바일 전용 레이아웃 — 사이드바가 하단 고정 가로 바로 전환, 폰트/버튼 축소, 플로팅 요소(AI 챗봇 등) 위치 조정

## 8. 접근성

- 포커스 표시: `outline:3px solid var(--primary)` + `outline-offset:3px` — 커스텀 버튼/카드/입력창 어디에도 반드시 유지
- 장식용 이미지/아이콘은 `aria-hidden="true"`, 의미있는 아이콘 버튼은 `aria-label` 필수
- 토글형 컨트롤(mic/cam, 팀 쉬는시간 잠금)은 `aria-pressed`/`role="switch"` + `aria-checked` 상태 갱신
- 실시간 피드백 영역은 `role="status" aria-live="polite"` 사용 (퀴즈 피드백, 토스트)
- 모달은 `role="dialog"` + `aria-label`, 배경 클릭과 ESC 없이도 명시적 닫기 버튼 제공
- 클릭 가능한 `<div>` 카드는 `role="button"` + `tabindex="0"` + `keydown`(Enter) 핸들러를 함께 붙여 키보드로도 접근 가능하게 합니다
- 터치 타깃 최소 44px 유지 (아동 사용자 대상 필수 기준, 선생님 화면 보조 버튼은 최소 38px)

## 10. 선생님 화면 전용 — 고령 사용자 접근성

선생님 화면(`teacher.html`)은 "예쁜 화면"보다 "헷갈리지 않는 화면"을 우선합니다. 낮은 대비, 작은 클릭 영역, 복잡한 단계, 낯선 용어는 사용을 크게 어렵게 만들 수 있습니다. 아래 규칙은 위 2~9장의 일반 규칙 위에 선생님 화면에서 추가로 지켜야 하는 것들입니다.

### 근거 — W3C가 말하는 고령 사용자 접근성

W3C는 고령·인지 접근성의 핵심을 **예측 가능성 · 읽기 쉬움 · 충분한 시간 · 오류 방지와 복구**로 설명합니다. 이 4가지는 그대로 선생님 업무 페이지에 적용됩니다. ([W3C Cognitive Accessibility](https://www.w3.org/WAI/cognitive/), [Older Users & Web](https://www.w3.org/WAI/older-users/developing/))

- **예측 가능성**: 같은 메뉴는 항상 같은 자리에, 같은 버튼은 항상 같은 뜻으로. 화면이 갑자기 바뀌거나 클릭 결과가 매번 다르면 안 됩니다. ([Predictable](https://www.w3.org/WAI/WCAG21/Understanding/predictable.html))
- **읽기 쉬움**: 큰 글자, 높은 대비, 짧고 쉬운 한국어. 고령 사용자에게도 WCAG A·AA 충족이 기본입니다. ([WAI-AGE 비교](https://www.w3.org/WAI/WAI-AGE/comparative.html))
- **충분한 시간**: 시간 제한을 두지 않거나, 두더라도 연장·해제할 수 있게. 자동으로 사라지는 안내(토스트)는 중요한 정보의 유일한 전달 수단이 되면 안 됩니다.
- **오류 방지와 복구**: 실수를 막고, 실수해도 쉽게 되돌릴 수 있게. 입력 보조·명확한 에러 안내·중복 입력 제거가 핵심입니다. ([WCAG 2.2 Understanding](https://www.w3.org/WAI/WCAG22/Understanding/))

이 서비스에서는 결국 아래 **5가지 축**을 계속 붙잡고 갑니다 — ① 사용자 맥락, ② 단순한 구조, ③ 높은 가독성, ④ 실수 방지, ⑤ 실제 테스트.

### ① 사용자 맥락 — 누가, 어떤 상황에서 쓰는가

선생님 화면은 여유롭게 둘러보는 서비스가 아니라 **수업 전후·행정 처리 중 바쁜 순간에 빨리 끝내야 하는 도구**입니다. 새 화면을 기획하기 전에 아래를 먼저 정합니다.

- 사용자는 나이 많은 선생님인가, 디지털이 익숙하지 않은 선생님인가, 둘 다인가
- 가장 자주 하는 일 3가지는 무엇인가 (예: 출석, 공지, 수업자료 확인) → 그 일을 홈 화면 최상단에 배치
- PC 위주인가, 태블릿·모바일도 함께 쓰는가
- 실수하면 가장 위험한 기능은 무엇인가 (저장, 삭제, 발송) → `.btn-danger` + 확인 절차 대상

### ② 단순한 구조 — 예측 가능하고 얕게

W3C는 페이지·기능이 **예측 가능**해야 사용자가 덜 헷갈린다고 봅니다. ([Predictable](https://www.w3.org/WAI/WCAG21/Understanding/predictable.html))

- 홈 화면에는 가장 중요한 기능 1~3개만 크게 배치 (히어로 카드 = "오늘 수업 시작하기", 그 아래 학급 카드 그리드)
- 메뉴 수를 줄이고 깊이를 얕게 — 원하는 기능을 **2번 이내 클릭**으로 찾게 합니다
- 한 화면에 주요 행동은 하나만 강조색(`--primary`)으로, 나머지는 톤 낮춤 (6장과 동일)
- **정보 확인 영역과 행동 버튼 영역을 명확히 분리** — 통계·세부 설정·관리 기능은 톱니바퀴(학급 관리) 안으로 숨겨 "지금 할 일"과 "관리/설정"을 화면 단위로 나눕니다 (0장 핵심 내비게이션 원칙)
- 같은 작업은 항상 같은 위치·같은 순서로 두어 화면 간 일관성을 지킵니다

### ③ 높은 가독성 — 크게, 대비 높게, 쉬운 말로

고령 사용자에게도 WCAG A·AA 충족이 기본입니다. ([WAI-AGE](https://www.w3.org/WAI/WAI-AGE/comparative.html), [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/))

- 본문·라벨·버튼 글자는 충분히 크게 (선생님 화면 주요 텍스트 최소 1rem, 3장 참고), 대비는 높게
- **색만으로 의미를 전달하지 않습니다** — 텍스트·아이콘을 함께 씁니다 (2장 규칙, 예: 마이크 꺼짐 = 빨강 + 빗금 아이콘)
- 키보드만으로도 모든 버튼·카드에 접근 가능하게 (8장 규칙)
- 버튼·클릭 영역을 넉넉하게 (최소 44px, 6장 규칙)
- 용어는 짧고 쉬운 한국어로 — 버튼은 "저장"이 아니라 "출석 저장"처럼 결과가 보이게 (6장 규칙)

### ④ 실수 방지와 복구 — 막고, 되돌리게

인지 접근성 지침은 **실수를 막고, 실수해도 쉽게 고칠 수 있게** 만드는 것을 중요하게 봅니다. ([Cognitive](https://www.w3.org/WAI/cognitive/), [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/))

- 입력칸마다 라벨과 예시를 명확히 (placeholder만으로 라벨을 대신하지 않음, 6장 규칙)
- 긴 폼은 단계별로 나누기 (`.wizard-dots`/`.wizard-step`, 6장 규칙)
- 에러 문구는 "왜 틀렸는지"보다 **"어떻게 고치면 되는지"** 를 바로 씁니다 (6장 규칙)
- 삭제·발송·수정·수업 종료처럼 되돌리기 어려운 행동은 `.btn-danger` + `confirm()` 확인 단계를 거치고, 위치도 주요 액션 버튼과 떨어뜨려 실수 클릭을 방지합니다
- 이미 입력한 정보를 다시 묻지 않습니다
- 처음 쓰는 기능 옆에는 1줄 설명, 새로 진입하는 화면(첫 학급/과제 생성 등)에는 짧은 단계 안내를 둡니다
- FAQ보다 "전화/채팅 문의" 버튼을 항상 눈에 띄게 둡니다 (사이드바 "문의하기")
- 저장·전송이 끝나면 `role="status" aria-live="polite"` 토스트로 결과를 크게 확인시킵니다 (8장 규칙). 단, 자동으로 사라지는 토스트가 중요한 정보의 **유일한** 전달 수단이 되지 않게 합니다

### ⑤ 실제 테스트 — 문헌만으로 끝내지 않기

문헌·체크리스트만으로는 부족하고, **실제 선생님이 써보는 관찰 테스트**가 문제를 가장 빨리 드러냅니다. 출시 전 최소한 아래를 직접 확인합니다.

- 첫 화면만 보고 **5초 안에** "무슨 화면인지" 이해되는가
- 원하는 기능을 **2번 이내 클릭**으로 찾는가
- 저장·수정·삭제를 헷갈리지 않는가
- 에러가 나도 혼자 복구할 수 있는가
- 마우스 없이 키보드만으로 버튼을 누를 수 있는가 (8장과 연결)
- 글자 크기·버튼 크기가 불편하지 않은가

## 11. 새 컴포넌트 만들 때 체크리스트

1. 이 화면의 핵심 기능이 기존 5색 중 어디에 속하는지 먼저 정하기 (Blue/Sky/Yellow/Mint/Gold 중 하나, 없으면 White 유지)
2. 카드 배경은 기본 흰색으로, 색은 헤더/아이콘/버튼/배지에만
3. Radius는 24px 이상 또는 완전 원형(입력창 16px, 작은 배지 14px까지 예외)
4. 인터랙션에는 `--bounce` 이징 + hover(부상)/active(팝) 두 상태 모두 정의
5. 버튼/터치 영역 44px 이상 (선생님 화면 보조 버튼은 38px 이상)
6. 모달/마법사가 필요하면 기존 `.modal-overlay`/`.modal-card`/`.wizard-dots` 패턴을 재사용
7. "일괄 제어"와 "개별 제어"가 공존하면 반드시 시각적으로 분리된 계층(상단 바 vs 개별 아이템)으로 배치
8. `prefers-reduced-motion`과 포커스 아웃라인이 깨지지 않는지 확인
9. 640px, 1120px 브레이크포인트에서 레이아웃 확인
10. 선생님 화면에 새 대시보드/리스트를 추가한다면 사이드바가 `align-self:stretch`를 유지하는지 확인
11. 선생님 화면에 새 기능을 추가한다면, "지금 가장 자주 쓰는 행동"이 화면 최상단에 노출되는지, 통계/설정은 하위로 빠졌는지 확인 (10장)
12. 버튼 텍스트가 동사+목적어로 구체적인지, 비슷한 버튼이 3개 이상 나란히 있지 않은지 확인
13. 폼이 3단계 이상이면 wizard로 분할했는지, 에러 문구가 해결 방법을 담고 있는지 확인
14. 상태 표시가 색만이 아니라 아이콘/텍스트를 함께 쓰는지 확인
15. (선생님 화면) 첫 화면 5초 이해 · 원하는 기능 2번 이내 클릭 · 같은 작업이 같은 위치에 있는지 확인 (10장 ②·⑤)
16. (선생님 화면) 되돌리기 어려운 행동에 확인 단계가 있고, 에러 문구가 해결 방법을 담고 있는지 확인 (10장 ④). 가능하면 실제 선생님 관찰 테스트로 검증
