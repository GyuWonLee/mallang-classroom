# 기능 분배 회의 자료 (2026-07-21)

> 참고 문서: [API 명세서 v0.4](api-spec.md) · [ERD v1.1](erd.md) · [아키텍처](architecture.md) · [컨벤션](conventions.md)

## 0. 회의 목표

1. 백엔드 도메인 묶음 4개 + 프론트 영역별 담당자 확정
2. 착수 순서 합의 (아래 로드맵 제안 기준)
3. 미결 사항 3건 결정 (섹션 5)

## 1. 현재 상태 — 개발 준비 완료

| 완료 항목 | 내용 |
|---|---|
| 인프라 | EC2 + HTTPS + Nginx, PostgreSQL(pgvector)/Redis, 로컬 개발 환경 |
| CI/CD | master 머지 → 백/프론트 자동 배포 + 헬스체크 (검증 완료) |
| WebRTC | LiveKit 가동, 화면공유 데모 + 12인 부하테스트 실측 (CPU 7.5%) |
| 문서 | API 55개 설계 확정, ERD 12테이블 확정, 인증 API Swagger 연동 완료 |
| 스캐폴딩 | Spring Boot 4.1 / React 19 빌드·배포 검증 완료 |

**→ 오늘 분배가 끝나면 내일부터 전원 병렬 개발 가능**

## 2. 백엔드 — 도메인 묶음 4개 제안

| 묶음 | 도메인 | API 규모 | 난이도 | 핵심 과업 |
|---|---|---|---|---|
| **A. 인증/계정** | 인증(5) + 초대/학생계정(7) | REST 12 | ★★☆ | JWT 발급/재발급(Redis), 학생 계정 자동 생성(alias+번호), CSV 일괄 등록, 초대 코드(Redis TTL) |
| **B. 학급/팀** | 학급(7) + 팀(6) | REST 13 | ★★☆ | 멤버십 권한 모델(OWNER/MAINTAINER), 학년별 팀 자동 배정, soft delete 정책 구현 |
| **C. 수업/실시간** | 수업(12) + 채팅(3) + STOMP(7 destinations) | REST 15 + 실시간 | ★★★ | LiveKit 토큰 발급(룸 2계층), 미디어 제어, 웹훅→프레즌스/출석, 화이트보드, 프레즌스 채팅 라우팅, 상태 스냅샷 |
| **D. 과제/AI** | 과제(8) + 학습이력(4) + 파일(3) | REST 15 | ★★☆ | JSONB 문제 스키마, LLM 비동기 생성(genjob Redis), 인증 파일 다운로드, TTS, 즉시 채점, 이해도 집계 |

**분배 가이드**
- C는 물리량은 보통이지만 **기술 난이도 최고** (LiveKit + STOMP + Redis 3종 세트) → 가장 실시간에 관심 있는 사람, 필요 시 2명
- A가 **모두의 선행 조건** → 가장 빨리 달릴 수 있는 사람
- D는 A/B와 독립적으로 개발 가능 (학급 ID만 있으면 됨) → 병렬화 최적
- 파일(9)은 D의 선행 조건이라 D에 포함

## 3. 프론트 — 화면 영역 제안

| 영역 | 화면 | 난이도 | 비고 |
|---|---|---|---|
| **가. 계정/학급 관리** | 로그인(선생님/학생), 학급 생성·관리, 학생 명단·CSV 업로드, 팀 편성 | ★★☆ | 백엔드 A·B와 짝 |
| **나. 수업 화면 (학생/선생님)** | LiveKit 룸 2계층 연결, 캠 타일, 화면공유 뷰, 화이트보드 캔버스, 손들기/채팅, 선생님 제어판(음소거·팀순회·판서권한) | ★★★ | **프로젝트 최대 화면**. 백엔드 C와 짝, 2명 권장 |
| **다. 과제/학습** | 과제 목록·풀이 UI(받아쓰기/객관식 렌더러), AI 과제 생성·검수 UI, 학습이력·이해도 대시보드 | ★★☆ | 백엔드 D와 짝. 문제 유형별 렌더러가 핵심 |

- 화이트보드 캔버스는 tldraw/Excalidraw 등 라이브러리 활용 전제
- 수업 화면은 학생용/선생님용이 사실상 다른 화면 → "나" 영역 2명 배정 근거

## 4. 착수 순서 제안 (의존성 기반)

```
        A(인증) ──→ B(학급/팀) ──→ C(수업/실시간)
                        └────────→ D(과제/AI)
```

| 주차 | 목표 |
|---|---|
| 1주차 | A 완성(로그인·JWT — 전원의 전제) + B 뼈대(학급·멤버십) + C/D는 A 없이 가능한 부분 선행(LiveKit 토큰 PoC, JSONB 스키마 설계, 프론트 레이아웃) |
| 2주차 | B 완성, C 핵심(수업 시작/입장/미디어 제어), D 핵심(과제 CRUD + 제출/채점) |
| 3주차 | C 심화(칠판·프레즌스 채팅·스냅샷), D 심화(AI 생성 + TTS), 통합 테스트 |
| 이후 | 이해도 분석, 스트레치 골(퀴즈·리액션·룰렛), 폴리싱 |

- 임시 계정/토큰 발급용 시드 데이터를 A 담당이 1주차 초에 제공 → 다른 묶음이 A 완성을 기다리지 않게

## 5. 오늘 결정할 것

1. **묶음별 담당자** — 위 A~D / 가~다 기준 (C·나는 인원 보강 여부 포함)
2. **스트레치 골 채택 여부** — 실시간 퀴즈/투표(추천, 이해도 데이터와 연결), 이모지 리액션, 랜덤 지목 룰렛, 발표자 스포트라이트, 집중 모드
3. **재제출 정책 확인** — 마감 전 재제출 허용, 모든 시도 이력 보존, 가장 최근 시도를 최종 성적으로 사용
